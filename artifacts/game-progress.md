## 当前结论

图片提示词的目标是“高品质跑跑卡丁车体验”，但当前项目已经是可玩的浏览器赛车样机，不应按从零开始的流程重建。当前优先级是提高已有系统的可读性、路线决策和英雄卡丁车辨识度，同时保持 `pilot-racer/1` 协议、服务端权威模拟和现有手机/大屏分工不变。

## 设计 brief

- 玩家承诺：用手机做出简单但有取舍的驾驶操作，在 60–120 秒内完成一场热闹、容易重赛的卡丁车比赛。
- 目标感受：第一圈学路线，第二圈用漂移和道具追回，最后一圈围绕超车和冲线形成高潮。
- 主动词：转向、漂移、喷射、使用道具。
- 5–30 秒循环：进弯找弯心 → 充漂移 → 松手小喷 → 选择是否抢道具箱。
- 1–5 分钟变化：赛道地标、弯道类型、名次掉率和导播事件让每圈决策不同。
- 非目标：不做拟真悬挂、不把手机变成 3D 渲染端、不替换现有联机协议、不为“高级感”堆未经验证的外部模型。

## 核心循环契约

玩家通过“选择路线并完成漂移”争夺更快的弯道出口，同时面对 AI、碰撞和道具压力；成功获得小喷、位置或道具优势，失误则损失速度但应能在下一段路线追回。

现有实现已经覆盖：输入、服务端权威速度/碰撞/道具、漂移双档奖励、AI 补位、圈次、冲线、重赛和导播反馈。升级重点不是新增一套规则，而是让这些收益在视觉和手机 HUD 上更早、更明确地被玩家理解。

## 三条升级线

### 1. 玩法：从“功能完整”到“决策清楚”

1. 在手机 HUD 增加下一弯提示：显示弯道方向、推荐入弯侧和“漂移收益/风险”短提示；不改变服务端判定。
2. 将漂移反馈统一为三个状态：蓄力、可小喷、完美喷射，并让大屏和手机使用同一套颜色语义。
3. 对道具箱做轻量的前后名次可读性提示：领先时偏防守，落后时偏追赶；保留服务端掉率与 pity 规则。
4. 保持 60–120 秒比赛时长，优先验证“每圈至少一次有效路线选择”和“落后仍有追回窗口”，不增加更多道具类型。

### 2. 地图：让赛道本身教会玩家

1. 海湾环线保留为入门图：强化海湾、桥、灯塔和终点拱门的视觉地标，作为学习漂移的路线。
2. 山脊赛道保留为进阶图：明确低速发卡弯、连续 S 弯和高低差入口，使用颜色、路肩和护栏提前预告风险。
3. 每张图只增加 1 个有意图的路线差异：内线短但窄、外线宽且更容易拿道具；不加入分叉迷宫。
4. 用重复地标帮助玩家判断圈次和位置，避免只靠 HUD 文本。

### 3. 卡丁车模型：先统一语言，再替换英雄车

1. 保持现有 8 车状态、碰撞盒和动画接口；所有外观模型继续以车身宽度、车头朝向和远距离轮廓可读为硬约束。
2. 统一五个视觉部件：车壳主色、前脸灯带、座舱/车手、轮胎/轮毂、尾部喷口。不同车辆只改变比例和材质，不改变操作性能。
3. 先把车 01 作为英雄模型打磨：车头色块、编号、轮胎接地阴影和氮气尾焰必须在大屏远景可辨。
4. Hyper3D 只作为候选资产源：先生成/导入一个低面数 GLB 并做比例、材质、包围盒和移动端加载评估；不通过评估就继续使用当前程序模型。
